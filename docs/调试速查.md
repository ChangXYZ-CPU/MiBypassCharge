## 状态与控制

```bash
sh $M/bin/bg-ctl.sh status      # 实时读 sysfs：LEVEL/CUR/POWER/BP/MODE/DAEMON/WATCH_RUNNING
sh $M/bin/bg-ctl.sh get         # 当前配置
sh $M/bin/bg-ctl.sh on          # 立即旁路（MODE=force_on）
sh $M/bin/bg-ctl.sh auto        # 恢复自动（默认模式）
sh $M/bin/bg-ctl.sh toggle      # 立即旁路 ↔ 恢复自动（WebUI 按钮就是调它）
sh $M/bin/bg-ctl.sh boot        # 拉起完整链路（supervise + daemon + watch）
sh $M/bin/bg-ctl.sh stop        # 停掉完整链路（先 smart_clear 松开停充位）
sh $M/bin/bg-ctl.sh restart     # 重启
sh $M/bin/bg-ctl.sh log 60
sh $M/bin/bg-ctl.sh set ENABLED 0|1          # 总开关：0=全停省电，1=恢复
sh $M/bin/bg-ctl.sh set WATCH 0|1            # 插拔即时响应
sh $M/bin/bg-ctl.sh set THRESHOLD_ON 90      # 停充点
sh $M/bin/bg-ctl.sh set THRESHOLD_OFF 85     # 恢复点，默认停充点−5
sh $M/bin/bg-ctl.sh set CHECK_INTERVAL 60    # 巡检间隔（5~120 秒）
```

> v1.7.2 起**没有 `resume` / `off` 命令**，也不再写 `MODE=force_off`（手动充电模式已废弃：
> 想正常充电直接关总开关）。老配置里的 `force_off` 会在读取时自动迁移成 `auto`。

## 轮询间隔（CHECK_INTERVAL 可调，默认 60 秒）

| 场景 | 间隔（默认 60 秒时） | 单核占用 |
|---|---|---|
| 插电、离停充点 ≤3% | 6 s（间隔/10，最小 3 s） | ~0.8% |
| 已在旁路中 / 插电中段 | 60 s | ~0.08% |
| 没插电 / 总开关关闭 | 120 s | ~0.04% |

间隔由 `bg-ctl set CHECK_INTERVAL N`（5~120 秒）调整，改完写配置并唤醒守护。
插拔即时响应（WATCH，默认开）另占约 0.233% 单核：靠 logcat 跟电池事件，插拔时即时叫醒守护，
关掉后插拔要等下一次巡检才发现。

## 守护结构

```
service.sh（开机）→ bg-ctl boot（ENABLED=0 时什么都不起）
                      ├─ bg-supervise.sh（看护：daemon 退出就重启，活着时零唤醒）
                      │    └─ bg-daemon.sh（主循环）
                      └─ bg-watch.sh（插拔监听，1 主 + 1 logcat 管道子）
```

完整停止/恢复用 `bg-ctl stop` / `bg-ctl boot`（会先 `smart_clear` 松开停充位，避免留下
"插电不充"）。手动 kill 时：
```bash
kill $(cat $D/supervisor.pid) $(cat $D/daemon.pid)
```
（不要用 `pkill -f bg-daemon.sh` —— 命令行里含同样字符串的 shell 会被自己杀掉）

## 手工验证旁路（只看电流，不看 status）

```bash
Q=/sys/class/qcom-battery
B=/sys/class/power_supply/battery

cat $B/current_now          # 负=充电，正=放电/停充
cat $B/status               # 旁路中可能是 Charging（滞后，别信）

# 按当前电量停充
LV=$(cat $B/capacity)
printf '0x%x\n' $(( (LV << 16) | 3 )) > $Q/smart_chg
sleep 5; cat $B/current_now                    # 应≈0
cat /sys/class/power_supply/usb/voltage_now    # 应仍在 9V 左右

# 解除（必须两步）
echo 0x2 > $Q/smart_chg; sleep 8
echo 0   > $Q/smart_chg; sleep 10
cat $B/current_now                             # 应回到 -3A 以下
```

| 现象 | 结论 |
|---|---|
| `current` ≈ 0，VBUS 还在 9V | 真旁路 ✔ |
| `current` 变正数（+0.4A）、VBUS 掉到 5V | 这是 `input_suspend` 的断充，手机在吃电池 ✘ |
| `current` 没变、还是 -4A | 掩码没生效（电量低位写错 / 节点被别的东西接管） |

## 排错对照

| 症状 | 先查 |
|---|---|
| 到阈值不停 | `cat $B/current_now` 是否≈0；`cat $Q/smart_chg` 非 0 即停充位已写；看 daemon 是否活着 |
| 停了又回充 | `log` 里有没有 `reassert`（驱动抢快充时守护会重写压回）；节点是不是被别的 App 改了 |
| 恢复充电慢 | 正常，PD 重协商要 10–20 s |
| 开关显示"未响应" | 刚开总开关 12 秒内是"启动中…"；持续未响应用 `bg-ctl boot` 补齐链路 |
| 充过阈值才停 | 该次 `CHECK_INTERVAL` 是否设得很大（120 秒粒度下快档窗口偏窄）；守护中途是否掉过线 |
| 卸载后不充电 | `echo 0x2 > $Q/smart_chg; sleep 8; echo 0 > $Q/smart_chg`；重启必然复位（sysfs 不落盘） |

## 卸载

KernelSU 移除模块即可。`uninstall.sh` 会两步复位 `smart_chg`、复位 `input_suspend`。
模块本身**不装任何 App**（v1.3 起去掉壳 App，纯 root 脚本 + WebUI）。
配置目录保留，彻底清理 `rm -rf /data/adb/bypass_guard`。
